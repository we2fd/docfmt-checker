# 测试用例与预期结果

> 本项目的验证分三层：**单元测试（101 个）** → **端到端自检（60 项）** → **浏览器 DOM 级断言**。
> 全部可一键复现，不依赖任何外部服务。

---

## 一、复现命令

```bash
# 第一层：101 个单元测试（解析 / 规则 / 引擎 / 修复 / 接口 / 模板反推）
cd backend && python -m pytest -q

# 第二层 + 第三层：端到端自检（真实端口起服务 + HTTP 全流程 + 无头 Chrome DOM 断言）
python scripts/selfcheck.py
```

`selfcheck.py` 会自行挑选空闲端口、使用隔离的临时数据目录（不污染 `data/`），
完成后输出 `artifacts/selfcheck-report.md` 与页面截图 `frontend-report.png`。

**当前状态：单元测试 101/101 通过，端到端自检 60/60 通过。**

### 用例 11：快速调整——不改 YAML 也能改阈值

| 项 | 内容 |
| --- | --- |
| **前置** | 服务已启动，切到「规则集 → 快速调整」 |
| **步骤** | ① 查看卡片数量；② 把「正文字号」从 12 改成 13.5；③ 卡片出现黄色「待保存」标记；④ 点保存；⑤ 故意填 9999 再保存 |
| **预期** | ① **30 张卡片、10 个分组**，每张给出单位与上下限；② 改完即标黄，页签显示「· 1 项待保存」；③ 保存后规则集里 `layout.body.size` = 13.5 磅；④ **9999 被服务端拦下**，且同批次其它改动不受影响 |
| **实际** | 30 项可调阈值分 10 组；12 → 13.5 磅；越界报「超出合理范围（5.0 ~ 100.0）」 ✅ |
| **设计意图** | 让**不懂 YAML 的人**（比如指导老师）也能改口径——这是"规则即数据"从"能改"到"好改"的补完 |

> 越界拦截放在**服务端**而不是只靠前端限制：前端限制能被绕过，
> 而一个 9999 磅的字号阈值会让规则永远判不合格，用户却不知道是自己填错了。

### 用例 12：参考模板校准——把学校模板读成规则

| 项 | 内容 |
| --- | --- |
| **前置** | 准备一份正文 14 磅、页边距 4cm 的 `.docx` 作为"学校模板" |
| **步骤** | ①「规则集 → 参考模板校准」上传该文件；② 查看建议表；③ **先不勾选**，回体检页检查一份文档；④ 回到校准页勾选并「应用」；⑤ 再检查同一份文档；⑥ 点「恢复内置默认」 |
| **预期** | ① 上方渲染出**格式画像表**（题目/各级标题/正文/摘要/关键词/题注/参考文献）；② 下方给出**逐条建议**：可推导 15 项、已一致 3 项、无阈值 19 项；③ 推导阶段**规则集一个字节都没变**（正文字号仍是 12 磅）；④ 应用后 `layout.body.size` = 14 磅，规则集说明里留下模板出处；⑤ 同一文档开始报"正文字号"问题；⑥ 恢复默认后回到 12 磅 |
| **实际** | 页面渲染 15 行建议、默认勾选 15 项、正文字号推导值 14 磅；应用后 14 磅、恢复后 12 磅 ✅ |
| **设计意图** | 内置规则是**通用口径**、不代表任何学校。要按本校要求检查，最"不靠猜"的办法就是**拿学校自己的模板当尺子** |

> ⚠️ 这里有一条重要的诚实边界：模板校准**推不出结构类规则**
> （标题不跳级、图表编号连续、必须含摘要）。它们判定的是"有没有 / 结构对不对"，
> 没有可量化的阈值。界面会直说「**没有可推导的阈值**」，而不是硬凑一个值出来。

## 四、端到端自检（60 项）

`python scripts/selfcheck.py` 自动执行并生成报告，分五个阶段：

### 阶段一：服务与配置（4 项）

| # | 检查项 | 结果 |
| --- | --- | --- |
| 1 | 服务在真实端口上启动并就绪 | ✅ |
| 2 | 接口 /config 返回规则集信息（56 规则 / 16 检查器 / 4 修复动作） | ✅ |
| 3 | 接口 /config 声明了「待人工确认」策略 | ✅ |
| 4 | 接口 /health 正常 | ✅ |

> **为什么坚持用真实端口而不是 TestClient**：TestClient 走进程内调用，
> 测不出静态资源 404、挂载路径错误、Vue 挂载失败这类问题——
> 而这恰恰是"页面打不开"最常见的原因。

## 五、开发过程中实际踩到并修复的坑

记录这些是因为它们都是**"看起来没问题、实际有问题"**的类型。

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | YAML 规则集加载失败 | 值里含"冒号+空格"（`年份: 页码`）被当成嵌套映射 | 给该值加双引号；并在错误提示里说明这一点 |
| 2 | 「中文,中文」被计为 2 处标点问题 | 多个正则交替匹配导致同一位置重复计数 | 合并为**单条含 4 个分支的正则**，一处只报一次 |
| 3 | 修复字号时报 `AttributeError: 'Run' object has no attribute 'direct_props'` | python-docx 的 `Run` 没有该属性，直接格式信息在我们自己的 `RunInfo` 里 | 改用 `run_info.direct_props`，并按**索引对齐**写回 `para.docx_paragraph.runs[position]` |
| 4 | 页码缺失的问题点「定位到原文」无反应 | `_issue()` 未初始化 `location.paragraph_index`，前端拿到 `undefined` | `_issue()` **把所有 location 键一律先置位**（值为 `None` 也算） |
| 5 | 接口 404 只有"Not Found"，用户不知下一步 | 未定义针对性的 `hint` | 为 get/delete 等补上可操作提示 |
| 6 | 无头 Chrome `--dump-dom` 拿到浏览器错误页 | 后台服务用 `&` 启动，shell 退出时被回收，端口已关 | 用后台任务方式启动 uvicorn，就绪后再取 DOM |
| 7 | CDP 连接 `ECONNREFUSED 9333` | Chrome 还在启动中 | 加 4 秒等待 + 轮询 `/json/version` 就绪后再驱动 |
| 8 | Element Plus 单选框不显示选中态 | 本地资源是 2.14.5，`el-radio-button` 的 `label` 已废弃 | 12 处全部改为 `value` |
| 9 | 雷达图坐标出现 `100.00000000000001` | 三角函数浮点误差 | 坐标统一保留 2 位小数 |
| 10 | Vue 页面显示正常但节点被静默丢弃 | in-DOM 模板里写了自闭合的自定义元素 `<el-input-number />`，浏览器把后续兄弟节点吞成它的子节点 | 所有 `el-*` 一律**显式闭合标签** |
| 11 | 删除文档在文件清理失败时整体报错（HTTP 500） | 原实现先 `unlink()` 再删数据库记录，`unlink` 抛异常就中断了整个删除 | **调换顺序**：先删元数据（保证用户可见的删除一定成功），再尽力清理磁盘文件并吞掉失败 |
| 12 | 字号阈值填 9999 竟然通过了校验，还算出 0.7 的容差 | 判断"是不是字体名"时用了 `prop.startswith("font")`，把 `font_size` 也匹配上了，`12` 被当成字符串 `"12"` | 改为**精确匹配** `FONT_PROPS = ("font_eastasia", "font_ascii")`，并抽成 `is_font_prop()` 供全文调用 |
| 13 | 自动容差对大字面值形同虚设（A4 宽 21cm 给出的容差是 ±1.05cm） | 容差按 `值 × 5%` 算，值一大就失控 | **加封顶**：`min(max(|value| × 5%, 下限), 0.5)` |
| 14 | 「保持不变」的建议却显示成了新数值（"21.0 倍 ~ 23.0 倍"） | 该规则虽然只换了容差、期望值没变，但代码仍去拼了新区间 | `unchanged` 状态直接给 `proposal_text = "保持不变"`，不再填 `proposal` |
| 15 | 自检结尾的汇总行始终不打印，退出码却是 0 | 沙箱禁止批量删除临时目录，`shutil.rmtree` 抛 `SystemExit`，把收尾逻辑一起带走了 | 抽一个 `safe_rmtree()` **捕获 `SystemExit`**；同理 `delete_template` 在 `unlink` 失败时改为归档到 `.trash/` |

> 第 10 条是最隐蔽的一条：**控制台零报错**，只是节点数量对不上。
> 判据是"修好后 DOM 长度明显变长"，所以端到端自检里会输出 DOM 字符数。
>
> 第 12 条是**"字符串前缀匹配"的经典反例**：`startswith` 看着很自然，
> 但它把语义上完全不同的两个属性（字体名 vs 字号）合并了。
> 更麻烦的是它**不报错**——只是悄悄地把数字变成字符串，
> 于是校验和容差全都在错误的类型上算，直到写出越界值 9999 才暴露。

## 六、已知边界

| 边界 | 现状 | 说明 |
| --- | --- | --- |
| 仅支持 `.docx` | 有意为之 | `.doc` / `.pdf` 拿不到样式继承信息，做不了这种精度的检查 |
| `unknown` 与 `pass` 的区分 | 对 14 个检查器生效 | 仅 `paragraph_run_uniform` / `blank_line_run` 声明为"空即通过"，因为这两条"没有对象"就是合格 |
| 中文字体别名 | 归一常见别名 | 依赖字体名映射表，罕见的第三方字体名可能识别不到（会落到 `unknown`） |
| 图表编号 | 支持「图 1」与「图 3-1」 | 不支持自定义编号格式（如「图 1.1.1」的任意层级） |
| 多节文档的页码 | 有默认页脚兜底检测 | 极端复杂的页眉页脚配置仍可能漏检（标为 `unknown` 而非误报） |
| 参考模板反推的**质量上限 = 模板本身** | 取众数 + 给出置信度 | 如果学校给的模板自己就不规范（比如正文混用 12pt 与 14pt），反推值会跟着模板走；因此置信度低于 80% 会标黄提示复核 |
| 参考模板推不出**结构类**阈值 | 明确标注「没有可推导的阈值」 | 标题不跳级、图表编号连续、必须含摘要这些判的是"有没有 / 结构对不对"，不存在可量化的数字 |
| 快速调整只覆盖**阈值型**参数 | 30 项 / 10 组 | `scope`、`checker`、`severity` 等结构字段仍需去「YAML 原文」页签改（有意为之：口径随学校变，逻辑不该被随手改） |
| 并发 | 单进程 | 面向个人/小团队使用，未做并发压测 |
