# 运行原理与讲解稿

> 这份文档回答两个问题：**它到底是怎么跑起来的**，以及**我该怎么讲给别人听**。
> 前者是技术，后者是表达——两件事都要准备，但准备的方式完全不同。

---

## 一、一句话说清它是什么

> **把"毕业论文格式规范"从人脑里的知识，变成程序能读的数据；
> 程序还原出文档每个格式值的真实来源，再拿规则集逐条比对，
> 产出带位置和整改建议的体检报告。**

这里有个关键说法要注意：**"格式规范"是数据，不是代码**。
这句话是整个项目的立足点，后面所有设计都由它推出来。

---

## 二、运行原理：五步流水线

```
① 上传 → ② 解析结构 → ③ 还原取值链 → ④ 规则逐条判定 → ⑤ 评分/报告/修复
```

### 第 1 步　上传与查重

- 校验扩展名；旧版 `.doc` 直接拦下，给出"另存为 .docx"的可操作提示
- 算文件的 **sha256**，命中就复用已有记录（不重复入库）
- 落盘 + 写入 `documents` 表

**为什么按 sha256 查重**：演示和自测时会反复载入同一份样例，
没有查重的话文档列表会迅速被重复项淹没。

### 第 2 步　解析文档结构

把 `.docx`（本质是一包 XML）解析成一个 `DocumentModel`：

- `paragraphs`　段落（**含表格内段落**，并打上 `in_table` 标记，防止表格文字被当正文误判）
- `sections`　　节：纸张尺寸、页边距、页眉页脚
- `headings`　　只收录真正的标题（优先看 Word 的 `outlineLvl` / 标题样式），
  避免把"摘要""关键词"这类结构性段落也算成标题
- `title` / `abstract` / `keywords` / `references`　题目、摘要、关键词、参考文献
- `figure_captions` / `table_captions`　图表题注
- `stats`　　段落数、字数、标题数

### 第 3 步　还原格式取值链　★ 本项目的核心

**问题**：Word 的格式不是"一个值"，而是**继承**出来的。
你在 Word 里看到某段是"宋体小四"，这个值可能来自四层中的任意一层：

```
文档默认值 docDefaults
      ↓ 被覆盖
基础样式（如「正文」）
      ↓ 被覆盖
派生样式链（样式自己还基于别的样式，沿 basedOn 回溯）
      ↓ 被覆盖
直接格式（用户在这一段上手动改的）  ← 优先级最高
```

**做法**：解析阶段对每个属性**同时记录两样东西**——

```python
class Value:
    value: Any            # 生效值（沿链自下而上找第一个"有值"的层）
    source: str           # missing | docDefault | style | direct
    style_id: str | None  # 若来自样式，记下是哪个样式
```

**为什么非要记来源**：因为**同一个"显示效果"，整改动作完全不同**。

| 报告里写的 | 用户该做什么 |
| --- | --- |
| 字号 12pt，来源 = 样式「正文」 | 与规范一致，无需处理 |
| 字号 14pt，来源 = **直接格式** | 清掉这一段的直接格式，让样式生效 |
| 字号 **未设**（整条链都没有） | 标为"待人工确认"，**不扣分、也不猜一个值** |

只报"实际值"是没有指导意义的——用户根本不知道去改样式、改文档默认值，还是改这一段。

**实现上的一个难点**：样式链要沿 `basedOn` 向上回溯，
而样式表里可能出现 `A basedOn B, B basedOn A` 这种**环形数据**，
朴素递归会死循环 → 必须带**环保护**。

### 第 4 步　规则集逐条判定

- 规则集从 YAML 加载成 `Ruleset`（内置 **56 条**）
- 引擎只认识 **16 种"判定方式"**（checker），
  完全不知道"论文要求 A4 纸"这类具体规定
- 对每条启用的规则：按 `checker` 名字取出对应函数 →
  传入 `(doc, rule, sections)` → 返回 `(fail_count, issues)`

**判定结果只有四种，而"哪些进分母"是这套设计里最讲究的地方**：

| 状态 | 含义 | 是否进评分分母 |
| --- | --- | --- |
| `pass` | 通过 | ✅ 进 |
| `fail` | 未通过，产出问题 | ✅ 进 |
| `unknown` | **本次文档中没有可判定的对象** | ❌ **不进** |
| `disabled` | 被用户在界面上停用 | ❌ 不进 |

`unknown` 是"宁可漏报不误报"的落地点。举例：
规则「参考文献著录要素完整」，若这篇论文压根没有参考文献章节——

- 判 `fail` → 白白扣分，用户莫名其妙；
- 判 `pass` → 掩盖了问题；
- **正确做法 → 标 `unknown`，归入"待人工确认"，且不计入分母。**

**例外**：有两条检查器声明为"空即通过"（`ZERO_IS_PASS`）——
「段落内格式统一」和「无连续空行」。因为"文档里没有连续空行"**本身就是合格**，
不是"无法判定"。如果不做这个区分，一份干净的论文会冒出十几个"待人工确认"。

### 第 5 步　评分、报告与保守修复

**评分四步**：

```
① 维度分 = 通过 ÷（通过 + 未通过）        # unknown / disabled 不进分母
② 加权求和 = Σ(维度分 × 权重)            # 排版 30% · 结构 30% · 一致性 20% · 内容 20%
③ 每条 error 级问题再扣 4 分              # 单次最多扣 30 分
④ 等级 = A≥90 · B≥80 · C≥70 · D≥60 · E<60
```

两个刻意的设计：

- **某维度全部 unknown → 整条从加权分母剔除**。
  否则一篇纯外文论文会因"没有中文标点问题"被无理由扣掉 20%。
- **error 只设 12 条（占 21%）**，全是"纸张、页边距、正文字体字号、章节缺失"
  这类一旦错就必须改的硬项。若把"字号一致性"也标成 error，
  一份只是略有瑕疵的论文会被扣到不及格，报告就失真了。

**报告**：Markdown 整改清单 + 可打印 HTML（样式内联，另存为单文件也能看）。

**保守修复**：只做 4 项**语义不变**的低风险操作——

| 动作 | 做什么 | 为什么不激进 |
| --- | --- | --- |
| `blank_lines` | 连续空段落压成 1 个 | 只删纯空段落 |
| `punctuation` | 中文语句里的半角标点改全角 | 只处理中文占比高的段落，跳过参考文献与表格 |
| `font_size` | 正文字号统一回"多数派" | **只改已经显式设置过**的，不给继承样式的段落新增直接格式 |
| `caption_numbering` | 图表题注重排为连续序号 | 保留"3-1"式章节前缀，只改数字不动文字 |

**而且永远生成新文件，原文件一个字节都不动。**

> 为什么不做全自动修复：Word 格式是继承的，给段落写直接格式会**把样式继承链焊死**，
> 用户后续改样式就失效了——这是"帮倒忙"。

## 三、附加层：阈值可配置（M6）

前五步解决的是"怎么按规则查"。但**规则从哪来**？内置的 56 条是
**本科论文通用口径**，不代表任何一所学校。所以补了两个功能：

### 3.1 快速调整

引擎自动扫描规则集，把**所有靠数字判定**的参数（`prop_equals` / `prop_range` /
`prop_in_set`）摊成一张表单，按"维度 → 对象"自动分组。
内置规则集里共 **30 项可调阈值、分 10 组**，每项自动配上**单位、合理上下限、步进**。

- 越界值在**服务端**拦下（字号输 9999 → "超出合理范围（5.0 ~ 100.0）"），
  且**一条坏值不会连累同批其它改动**
- 只允许改 5 个阈值类键；想改 `scope` / `checker` 这类结构字段会被拒绝并指路 YAML 页签

> 为什么这条限制重要：**阈值是"口径"，结构是"逻辑"**。口径随学校变，逻辑不该被随手改。

### 3.2 参考模板校准　★ 零硬编码

**它做的事**：上传一份学校模板 `.docx`，逐条量出它在每条规则对应属性上的实际值，
反推出建议阈值，**用户勾选后才写回规则集**。

**为什么能做到零硬编码**（这是最值得讲的一点）：
规则自己在 YAML 里已经声明了"判哪类对象、判哪个属性"——

```yaml
params:
  scope: body        # 判哪类对象
  prop: font_size    # 判哪个属性
```

于是"量模板"这件事可以直接**复用引擎自己的两个原语**：

```python
paras = select(doc, rule.params["scope"])            # 取到"正文"这一类段落
vals  = [get_prop(p, rule.params["prop"]) for p in paras]   # 量出每段的实际值
```

上层完全不知道 `body` 是什么、`font_size` 是什么。
→ **新增一条阈值型规则，三个功能自动认识它，不用维护任何映射表。**

**四条设计约束**：

| 约束 | 做法 | 理由 |
| --- | --- | --- |
| 取**众数**不取平均 | 取出现次数最多的值 | 模板里"正文"有上百段，平均会被个别异常段拉偏 |
| 每个建议带**置信度** | 众数次数 ÷ 有效样本数，<80% 界面标黄 | 让用户知道这个值有多可信，而不是照单全收 |
| 无阈值就**明说** | 结构类规则标 `not_applicable` | "标题不跳级"判的是结构对不对，没有可量化的数字 |
| **只推导不自动应用** | `profile` 阶段纯只读，`apply` 才写回 | 规则的改动必须是**用户按下的** |

应用后会在规则集说明里留下出处：`（阈值已按参考模板「XX」校准 · 日期）`，
下次有人问"这套阈值哪来的"，规则集自己就能回答。

**实测**（用一份正文 14 磅、页边距 4cm 的模板）：
可推导 15 项 / 已一致 3 项 / 无阈值 19 项；推导阶段规则集**一个字节都没变**。

## 四、怎么跟老师说

### 4.1 讲之前先想清楚一件事

老师听课程设计/毕设，判断的不是"你的技术难不难"，
而是这三样：

1. **你是否真的理解自己做的东西**（而不是拼凑了别人的代码）
2. **你有没有自己的判断**（哪里做了取舍、为什么）
3. **你凭什么说它能用**（有没有可复现的验证）

所以话术的目标不是"显得厉害"，而是**让对方相信你是个想清楚了的作者**。

### 4.2 一句话版（约 30 秒，用于开场或电梯陈述）

> "我做的工具是把论文格式规范变成可执行的数据。论文拖进去，
> 它会还原出文档里每个格式值的真实来源，再拿规则集逐条比对，
> 三秒出一份带位置和整改建议的体检报告。
> **技术上不复杂，但我把三件容易做错的事做对了：判不准就不判、
> 每个值都追溯来源、修复只做不会改坏文档的操作。**"

### 4.3 三分钟版（四个要点，按这个顺序讲）

**要点一：问题的真正难点不在"对比数值"，在"值从哪来"**

> "看起来只是拿文档的实际字号去比对规定字号。但 Word 的格式是继承的——
> 一个段落显示 14 磅，可能是这一段被手动改过，也可能是整个样式定义就是错的，
> 或者是文档默认值的问题。**这三者的整改动作完全不同**。
> 所以我解析时会同时记录生效值和它的来源，这样报告才能告诉用户'该改哪儿'。"

**要点二：规则不写死在代码里，而是写成数据**

> "整个引擎有 56 条规则，全部写在 YAML 里。引擎只认识 16 种判定方式，
> 完全不知道'论文要求 A4 纸'这类具体规定。所以**换一套学校规范，
> 只需要换一份 YAML，代码一行不动**。"

**要点三：判不准的时候明确说判不准**

> "这是我最在意的一个设计。规则遇到'本次文档里没有可判定的对象'时，
> 我不会判它合格也不会判它不合格，而是标成'待人工确认'，
> **并且不计入评分分母**。因为格式检查工具最大的风险不是漏报，而是**误报**——
> 一份报告里出现三个假警报，用户就再也不会信任它了。"

**要点四：有可复现的验证，不是演示品**

> "项目自带两套验证：**101 个单元测试**，覆盖解析、规则、引擎、修复、接口、模板反推；
> **60 项端到端自检**——用真实端口起服务、走完整 HTTP 流程，
> 再启动无头浏览器对**真实渲染后的 DOM** 做断言，
> 包括'前端框架是否真的挂载了''有没有 JS 异常'。"

### 4.4 深挖版（老师追问技术细节时）

按这个顺序展开，每层都比上一层深一档：

1. **取值链怎么实现的** → 沿 `basedOn` 回溯 + `docDefaults` + 直接格式，取第一个有值的层；带环保护
2. **16 个检查器怎么划分的** → 按**判定方式**而不是按业务规则划分，所以复用力高（20 条规则共用 `prop_equals`）
3. **评分为什么这么设计** → `unknown` 不进分母；全 unknown 的维度整条剔除并重新归一化权重
4. **修复为什么只做 4 项** → 直接格式会焊死样式链；且语义不变才敢改
5. **模板反推为什么不用映射表** → 规则自带 `scope`/`prop`，直接复用引擎的 `select()` + `get_prop()`

## 五、老师最可能追问的问题（含答法）

**Q1　这跟 Word 自带的检查、或者网上的格式检查工具，区别在哪？**

> 类比很准确，我确实把它当"论文格式的 linter"来做。
> 但关键差异在**判断的粒度**：普通检查只看"值对不对"，
> 我额外记录了**值的来源**，因为来源决定整改动作。
> 另外是**对不确定性的处理**——判不准的明确标注且不扣分，这决定了报告能不能被信任。

**Q2　你这 56 条规则的依据是什么？**

> 我标的是「本科毕业论文格式规范（通用版）」，阈值来自公开的本科论文写作通识要求——
> A4 纸、上下 2.5cm、左 3.0cm、正文宋体小四、1.5 倍行距这一类，
> **不是**从任何一所学校的正式文件抄的，我也没有任何学校的授权。
>
> 正因为"通用口径 ≠ 你们学校的要求"，我才专门做了两个功能去解决它：
> 「快速调整」让口径随手可改，「参考模板校准」直接拿**学校自己的模板**当尺子反推。
> **这个工具不假装自己知道你们学校的规定，它提供的是"把规定变成可执行规则"的能力。**

> ⚠️ **这是最容易被问倒的问题，务必按上面的口径答。**
> 千万不要说"这是教育部的规定""这是学校的标准"——拿不出依据，一旦被追问会很被动。

**Q3　怎么保证它不误报？**

> 三条措施：
> ① 判不准的标 `unknown`，不进评分分母；
> ② 内置一份**完全合规的样本**，端到端自检里断言它必须是 100 分、零问题——这是回归守卫；
> ③ 一致性检查取**多数派**而非第一个样本，
>    否则第一个标题恰好写错，会导致其余 20 个正确标题全被误报。

**Q4　Word 的格式那么复杂，你怎么知道某个字号的真实值？**

> 我沿 `basedOn` 向上回溯到样式链顶端，再往下找 `docDefaults`，
> 取第一个出现的值作为生效值，并记录它来自哪一层。样式表有环的话有保护，不会死循环。
> **如果整条链都没有 → 标 `unknown`（需人工确认），而不是猜一个值。**

**Q5　为什么不干脆做全自动修复？**

> 两个原因：一是 Word 格式是继承的，给段落写直接格式会**把样式继承链焊死**，
> 用户后续改样式就失效了——这是"帮倒忙"；
> 二是有些格式问题**需要人的判断**，比如标题层级不合理，机器不知道怎么调。
> 所以我只做 4 项语义不变的操作，且永不覆盖原文件。
> 同样的克制也用在模板校准上：推导完**不自动应用**，必须用户勾选确认。

**Q6　参考模板校准不就是抄模板吗？有什么技术含量？**

> 表面看是"量一遍模板"，但要点在于**它没有硬编码任何映射表**。
> 规则自己在 YAML 里就声明了"判哪类对象、判哪个属性"，
> 所以反推逻辑直接复用了引擎自己的取值函数——
> **以后加一条新规则，这个功能自动就认识它**，不需要改任何代码。
> 另外取值取的是**众数**而不是平均（模板里"正文"上百段，平均会被异常段带偏），
> 并且给出**置信度**：占得低就说明模板自己就不统一，界面会标黄提示复核。

**Q7　那我上传的模板自己就不规范呢？**

> 这正是置信度存在的原因。反推取的是众数，也就是"模板里大多数正文段落长什么样"，
> 同时给出这个众数占多少比例。占得低就说明模板自己不统一，界面会**标黄**提示复核，
> 而不是悄悄按它改。另外还有三道兜底：推导结果默认只是建议、应用时要过一遍取值范围校验、
> 随时可以一键恢复内置默认。
> **换句话说：它把模板当作"证据"而不是"真理"。**

**Q8　有什么没做完的？**

> 四个明确的边界：
> ① 只支持 `.docx`，因为 `.pdf` / `.doc` 拿不到样式继承信息；
> ② 图表编号只支持"图 1"和"图 3-1"两种形式，不支持任意层级；
> ③ 参考模板**推不出结构类阈值**——"标题不跳级"这种判的是结构对不对，
>    没有可量化的数字，界面上会明说"没有可推导的阈值"；
> ④ 单进程，没做并发压测——它是面向个人/小团队的工具。
>

## 六、不要说的话（容易翻车）

| 别说 | 为什么 | 改成说 |
| --- | --- | --- |
| "这是教育部/学校规定的标准" | 你拿不出依据，一追问就崩 | "通用口径，不是任何学校的正式文件" |
| "准确率 100% / 零误报" | 只对 4 份样例验证过，不是普适结论 | "内置合规样本实测零误报，这是回归守卫" |
| "能自动把论文改好" | 只做 4 项低风险操作，且不改原文件 | "只做语义不变的操作，永远生成新文件" |
| "这是我的创新点"（说得很虚） | 容易被反问"这也算创新？" | "这是我自己想清楚的取舍：为什么这么设计" |
| "用了 AI / 大模型" | 本项目**没有**用，说了反而被追问 | 不提；核心是规则引擎不是模型 |
| "代码量很大所以工作量足" | 行数不是价值 | "101 个测试 + 60 项自检，这部分比写功能还费时间" |

## 七、一页速查（讲前扫一眼）

**数字**

| 项 | 值 |
| --- | --- |
| 内置规则 | 56 条（排版 28 / 结构 10 / 一致性 13 / 内容 5） |
| 判定方式（检查器） | 16 种 |
| 修复动作 | 4 项 |
| 可调阈值 | 30 项 / 10 组 |
| 接口 | 26 个 |
| 单元测试 | **101** 个 |
| 端到端自检 | **60** 项 |
| 样例体检分 | 100 / 46 / 71 / 66 |
| 代码量 | 约 1.1 万行（core 3250 / tests 1780 / 前端 2280 / 规则集 568） |

**三个"我想清楚了"**

1. **判不准就不判**　无法判定的项标"待人工确认"，且不计入扣分
2. **说清楚"从哪来"**　每个格式值追溯来源，每个阈值追溯出处
3. **不替用户做决定**　修复要保守，规则改动必须是用户按下去的

**三个技术要点**

1. **格式取值链**　生效值 + 来源（`direct` / `style` / `docDefault` / `missing`）
2. **规则即数据**　56 条规则在 YAML，16 个检查器在代码；同一份数据被引擎、快速调整、模板校准三方读取
3. **零硬编码反推**　复用规则的 `scope` / `prop`，新增规则自动被覆盖

**验证两句话**

```bash
cd backend && python -m pytest -q     # 101 passed
python scripts/selfcheck.py           # 60/60
```
