现场把「正文字号」从 12 改成 13.5 → 卡片变黄、页签提示"· 1 项待保存" → 保存。

### 3:25–4:15　演示「参考模板校准」（本版本最亮的点）

切到「参考模板校准」子页签，上传事先准备好的那份"学校模板"。

> "刚才那两条路都还是'人来想数值'。但真实场景是这样的：
> **学校给了你一份模板，你不会关心它到底是多少磅，你只想要'就按这个模板查'。**
> 所以我做了这个：你上传模板，它自己去把模板量一遍。"

上传后：
- 上方出现**格式画像表**（题目 / 各级标题 / 正文 / 摘要 / 关键词 / 题注 / 参考文献）；
- 下方出现**逐条建议**：可推导 15 项、已一致 3 项、无阈值 19 项。

重点讲**三件事**：

> "第一，**它没有硬编码任何映射表**。规则自己在 YAML 里就声明了'我判哪类对象、
> 判哪个属性'，所以反推逻辑直接复用引擎自己的取值函数——
> **以后加一条新规则，这个功能自动就认识它**。
>
> 第二，**取值取众数、不取平均**。一份模板里'正文'有上百段，
> 取平均会被个别异常段拉偏；而且每个建议都标了**置信度**，低于 80% 会标黄提醒复核。
>
> 第三，也是最关键的——**推导阶段一个字节都不改规则**。你看，
> 正文字号现在还是 12 磅。只有我勾选、点'应用'，它才会变成 14 磅。"

点应用 → 回体检页重新检查 → 原来合规的文档开始报"正文字号"问题。

> "而且规则集里会自动留下出处：'阈值已按参考模板「XX」校准'。
> 下次有人问这套阈值哪来的，规则集自己就能回答。"

补一句诚实边界：

> "有一点它推不出来：标题跳级、图表编号连续、必须含摘要这些**结构类**规则。
> 因为它们判的是'有没有、结构对不对'，不存在一个能从模板里读出来的数字。
> 界面上会直说'**没有可推导的阈值**'——**不会就是不会，我不硬凑。**"

## 二、四个技术亮点（展开讲的话术）

### 亮点一：格式取值链（最核心）

**问题**：Word 的格式是继承的。一个段落显示为宋体小四，可能来自
直接格式 / 样式链 / 文档默认值。只报"实际值"，用户不知道该改哪儿。

**做法**：解析阶段对每个属性同时记录**生效值 + 来源**。

```python
class Value:
    value: Any            # 生效值
    source: str           # missing | docDefault | style | direct
    style_id: str | None  # 若来自样式，记下是哪个
```

继承顺序：`docDefaults < 基础样式 < 派生样式链 < 直接格式`

**难点**：样式链要沿 `basedOn` 向上回溯，且必须有**环保护**——
样式表里出现 `A basedOn B, B basedOn A` 会让朴素递归死循环。

### 亮点二：规则即数据

56 条规则在 YAML，16 个检查器在代码里。引擎不认识"论文要求"。

```yaml
- id: layout.body.size
  name: 正文字号
  category: layout
  severity: error
  checker: prop_equals
  params: { prop: font_size, expected: 12, tol: 0.5 }
  suggestion: 选中正文 → 开始 → 字体 → 字号选「小四」
```

**收益**：
- 换规范 = 换 YAML；
- 规则可被老师在界面上改，错误提示必须可操作（"未知的 checker『xxx』，可用值见…"）；
- 检查器按**判定方式**而非业务规则划分，复用力高——20 条规则共用 `prop_equals`。

### 亮点三：评分设计里的「宁可漏报」

```
维度分 = pass / (pass + fail)      # unknown 与 disabled 不进分母
总分   = Σ(维度分 × 权重) / Σ(参与权重)
```

- 某维度**全部 unknown** → 该维度 `score = None`，从加权分母剔除。
  （否则一篇纯外文论文会因"没有中文标点问题"被无理由扣 20%。）
- `error` 只设 12 条（占 21%），全是纸张/页边距/正文字体字号/章节缺失这类硬项。
  若把"字号一致性"也标 error，稍有瑕疵的论文会被扣到不及格，报告失真。
- 两类检查器声明为「空即通过」：

```python
ZERO_IS_PASS = {"paragraph_run_uniform", "blank_line_run"}
```

因为"文档里没有连续空行"本身就是合格，不是"无法判定"。

### 亮点四：规则反推里没有一行映射表

**问题**：改阈值的两条路——手填表单、按模板反推——看起来都需要一份
"规则 → 该量模板哪个属性"的映射表。56 条规则就有 56 行，而且**加一条规则就得改一次**。

**做法**：不需要。因为规则在 YAML 里已经**自带元信息**：

```yaml
params:
  scope: body        # 判哪类对象
  prop: font_size    # 判哪个属性
```

所以"量模板"直接复用引擎自己的原语：

```python
paras = select(doc, rule.params["scope"])
vals  = [get_prop(p, rule.params["prop"]) for p in paras]
```

**收益**：这条管线**对规则数量的增长是免费的**——新增一条阈值型规则，
「快速调整」会自动把它摊成表单卡片，「参考模板校准」会自动去量它。

**配套的两个判断**：
- 取**众数**而非平均（模板里"正文"上百段，平均会被异常段带偏），并给出**置信度**；
- 结构类规则**明说推不出来**，而不是硬凑一个数字出来。

> 这一条的真正价值不在技术难度，而在**它把"规则"从"给代码看的配置"
> 变成了"给程序读的、自带语义的数据"**——同一个数据，引擎读它做检查、
> 表单读它做界面、反推读它做校准。

## 三、预设问答

**Q0：你这些规则的阈值，是根据什么定的？**

> 说清楚：内置的 56 条我标的是「**本科毕业论文格式规范（通用版）**」，
> 阈值来自公开的本科论文写作通识要求——A4 纸、上下 2.5cm、左 3.0cm、
> 正文宋体小四、1.5 倍行距这一类，**不是**从任何一所学校的正式文件里抄的，
> 我也没有任何学校的授权。
>
> 正因为"通用口径 ≠ 你们学校的要求"，我才专门设计了两个功能去解决它：
> 「**快速调整**」让口径随手可改，「**参考模板校准**」直接拿**学校自己的模板**
> 当尺子反推。也就是说，这个工具**不假装自己知道你们学校的规定**，
> 它提供的是"把规定变成可执行规则"的能力。

**Q1：你这个和创新点在哪？不就是一个 linter 吗？**

> 类比很准确，我确实把它当"论文格式的 linter"来设计。
> 但关键差异在**判断的粒度**：普通检查只看"值对不对"，
> 我额外记录了**值的来源**，因为来源决定整改动作。
> 另外就是**对不确定性的处理**——无法判定明确标注且不扣分，
> 这决定了报告能不能被信任。技术上不炫，但这两个设计点是我自己想清楚才做的。

**Q2：为什么不自动修复？全自动不是更方便吗？**

> 我刻意没做。原因有两个：
> 一是 Word 格式是继承的，给段落写直接格式会**把样式继承链焊死**，
> 用户后续改样式就失效了——这是"帮倒忙"；
> 二是格式错误里有一部分**需要人的判断**，比如标题层级不合理，
> 机器不知道该怎么调。
> 所以我只做 4 项**语义不变**的操作，且永不覆盖原文件。
> 同样的克制也用在**参考模板校准**上：推导完**不自动应用**，
> 必须用户勾选确认——**规则的改动应该是人按下的。**

**Q3：怎么保证它不误报？**

> 三条措施：
> ① 判不准的标 `unknown`，不进评分分母；
> ② 内置一份**完全合规的样本**（`01-规范样本.docx`），
>    端到端自检里断言它必须是 100 分、零问题——这是回归守卫；
> ③ 一致性检查取**多数派**而非第一个样本，
>    否则第一个标题恰好是错的会导致其余全被误报。

**Q4：规则集写错了会怎样？**

> 分两层：语法错误会给出**带行列号和 `^` 指示**的 YAML 报错；
> 语义错误（未知 checker、缺必填参数、非法 category）在解析阶段逐条校验，
> 报错精确到"哪条规则、哪个字段、可用值是什么"。
> 因为规则集是**给老师改的**，错误提示的质量直接决定这个功能能不能用。
> 「快速调整」这条路径上还多加了一道：**越界阈值在服务端就被拦下**，
> 而且**一条坏值不会连累同批其它改动**。

**Q5：如果文档里字体的设置藏在很深的样式链里呢？**

> 我沿 `basedOn` 向上回溯到样式链顶端，再往下找 `docDefaults`，
> 取**第一个出现的值**作为生效值，并记录它来自哪一层。
> 样式表有环的话有保护，不会死循环。
> 如果整条链都没有 → 标 `unknown`（需人工确认），而不是猜一个值。

**Q6：**（针对模板校准）**我上传的模板自己就不规范，怎么办？**

> 这正是我做**置信度**的原因。反推取的是**众数**，也就是"这份模板里大多数
> 正文段落长什么样"，同时给出这个众数占了多少比例。占得低就说明模板自己
> 就不统一——界面会**标黄**提示复核，而不是悄悄按它改。
>
> 另外有三道兜底：
> ① 推导结果**默认只是建议**，不点应用不生效；
> ② 应用时还要过一遍**取值域校验**（字号 5~100 磅之类），离谱值进不去；
> ③ 随时可以「一键恢复内置默认」。
>
> 换句话说：**它把模板当作'证据'而不是'真理'**——量出来是什么就报什么，
> 可不可信由置信度告诉你，采不采纳由你决定。

**Q7：为什么不用数据库/框架？**

> 三张表、查询简单，用标准库 `sqlite3` 就够，**少一个依赖**，
> 而且 SQL 全在代码里可读可讲。
> 前端用全局构建版 Vue，**免 Node 环境、免 `npm install`、断网可跑**——
> 答辩现场最怕的就是装环境装一半卡住。

**Q8：这个工作量有多少？**

> 全项目约 **1.1 万行**（后端 + 前端 + 脚本 + 规则集，含测试）。拆开看：
> 核心引擎 `core/` 约 **3250 行**（解析+规则+检查+修复+报告+模板反推），
> 接口与服务层约 1200 行，测试约 **1780 行**，前端约 **2280 行**，规则集 568 行。
> 工作重心在两块：一是**取值链解析**（需要对 OOXML 有基本了解），
> 二是**测试与自检**——**101 个单元测试 + 60 项端到端自检**，
> 这部分花的时间比写功能还多，但它保证了"说它能用就是真能用"。

**Q9：有什么没做完的？**

> 四个明确的边界：
> ① 只支持 `.docx`，因为 `.pdf` / `.doc` 拿不到样式继承信息；
> ② 图表编号只支持"图 1"和"图 3-1"两种形式，不支持任意层级；
> ③ **参考模板推不出结构类阈值**——"标题不跳级"这种判的是结构对不对，
>    没有可量化的数字，界面上会明说；
> ④ 单进程，没做并发压测——它是面向个人/小团队的工具。
> 这些我都写进了 `docs/测试用例与预期结果.md` 的"已知边界"一节，
> 我认为**说清边界比假装没有边界更专业**。

**Q10：你这个能用到实际场景吗？**

> 能，而且我做了四件事让它不只是个玩具：
> ① 内置 4 份演示样例 + 一键载入，不用准备素材就能上手；
> ② 规则集可以在界面上直接改阈值，不用碰 YAML；
> ③ **手上有学校模板的话，上传一下就能按本校要求检查**——这是最接近真实使用的路径；
> ④ 核心引擎不依赖 Web 框架，将来要加"批量扫描一个目录"很容易——
>    五十行脚本就够。

## 四、一句话总结（备用）

> **它不生成内容、不代替写作，只把"对着格式规范逐条抠文档"这件事自动化，
> 并且明确告诉你：哪里不对、为什么不对、该怎么改、以及哪些地方它判不准。**

如果要再补一句，就补这句：

> **而且它不假装自己知道你们学校的规定——内置的只是一套通用口径；
> 你们学校真正的规范，可以用你们的模板直接交给它。**
