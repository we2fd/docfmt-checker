# 格致 · 学术文档格式智能检查与规范化助手

> **DocFmtChecker** —— 把一篇毕业论文 `.docx` 拖进来，三秒内得到一份「格式体检报告」：
> 每条问题都告诉你 **在哪里、现在是什么、规范要求是什么、怎么改**；
> 报告可导出、可打印，低风险问题还能一键生成修正稿（**绝不覆盖原文件**）。

这是一个面向「毕业论文格式审查」场景的轻量级 Web 工具。
它不生成内容、不代替写作，只做一件很实在的事：**把人从"对着格式规范逐条抠文档"里解放出来。**

---

## 一、它解决什么问题

毕业论文的格式规范通常是一份十几页的 PDF：字号、行距、页边距、标题层级、图表编号、
参考文献著录格式……学生在交稿前手工自查一遍要花掉大半天，还极易漏项；
指导老师收到稿子后又要重复检查一遍。

**这个工具把"格式规范"变成了一份可执行的数据文件**（YAML 规则集），
文档解析后逐条比对，输出结构化的问题清单。

三条设计原则贯穿始终：

| 原则 | 含义 | 为什么重要 |
| --- | --- | --- |
| **宁可漏报，不可误报** | 判不准的项目标为「待人工确认」，不计入扣分 | 一份报告有 3 个假警报，用户就再也不会信任它 |
| **格式问题要说清"从哪继承来的"** | 每条属性都记录取值来源（直接格式／样式／文档默认值） | 同一段"看起来是宋代小四"，来源不同，改法完全不同 |
| **修复必须保守** | 只做 4 种低风险操作，永远生成新文件 | 全自动改写会破坏用户的样式体系，风险不可接受 |

## 二、快速开始

### 1. 环境要求

- Python **3.10+**（开发与验证使用 3.13）
- 无需 Node.js、无需联网、无需数据库服务
- 依赖：`fastapi` `uvicorn` `python-docx` `pyyaml` `pydantic`（测试另需 `pytest` `httpx`）

### 2. 安装依赖

```bash
pip install fastapi uvicorn python-docx pyyaml pydantic
# 想跑测试再装：
pip install pytest httpx
```

### 3. 启动

**推荐用一键启动脚本**（自动找空闲端口、自动打开浏览器）：

```bash
python run.py                 # 默认 127.0.0.1:8300，会自动打开浏览器
python run.py --port 8301     # 指定端口
python run.py --no-browser    # 不自动打开浏览器
```

Windows 上也可以直接双击 **`start.bat`**。

如果你更习惯手工起服务：

```bash
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8300
```

浏览器打开 **http://127.0.0.1:8300** 即可。

> 前端为 Vue 3 + Element Plus，**所有资源已本地化**（`frontend/assets/`），
> 断网环境下同样可正常渲染与交互。

### 3.5 打包成免安装便携版（拷 U 盘带走）

目标电脑**没装 Python、没联网**也能跑：

```bash
python scripts/build_portable.py             # 输出 F:/wbwork/docfmt-portable + 同名 zip
python scripts/build_portable.py --clean     # 重建
python scripts/build_portable.py --no-zip    # 只要目录
```

产物 ~44 MB（zip ~19 MB），结构：

```
docfmt-portable/
├─ START.bat        双击启动（主入口）
├─ 自检.bat         端到端自检，验证这个包在目标机器上真的能用
├─ 使用说明.txt     面向使用者的中文说明
├─ python/          内嵌 Python 3.13 运行时 + 全部依赖（与系统环境完全隔离）
├─ backend/ frontend/ samples/ scripts/ docs/
└─ run.py
```

三点实现要点（都是踩过才写对的）：

1. **依赖按真实闭包精确拷贝**，不是把整个 venv 的 site-packages 搬过去 ——
   本机 venv 里还有另一个项目的重依赖，全搬会白白多出上百 MB；
2. `python313._pth` 必须显式加上 `Lib\site-packages` 与 `import site`，
   否则 embed 版的隔离模式会让第三方包**一律 import 不到**；
3. **`python-multipart` 要手工加进依赖清单** —— 它不在 FastAPI 的依赖元数据里
   （FastAPI 只在解析上传表单时才 import 它），漏了它上传接口会直接 500。

## 四、核心功能一览

| 模块 | 能力 |
| --- | --- |
| **M1 规则集** | 56 条规则全部写在 YAML 里，改规则**不用改代码**；支持在界面上启停单条规则、查看 YAML 原文、一键恢复内置默认 |
| **M2 文档解析** | 逐段解析 .docx，记录每个属性的**生效值 + 取值来源**（直接格式／样式／文档默认值／缺失）；识别标题、摘要、关键词、参考文献、图表题注、页脚 |
| **M3 检查引擎** | 16 个通用检查器驱动 56 条规则；覆盖排版、结构、一致性、内容四个维度；带**四维度加权评分** |
| **M4 报告输出** | 结构化问题清单（位置 + 实际值 + 期望值 + 整改建议）、SVG 四维雷达图、原文对照高亮、可导出 Markdown 整改清单与可打印 HTML 报告 |
| **M5 保守修复** | 4 种低风险操作：压缩空行 / 统一标点 / 统一正文字号 / 重排图表编号；修复前后对比，产出新文件供下载 |
| **M6 阈值可配置** | ①「快速调整」：把规则里靠数字判定的项（字号、行距、页边距、缩进、字数区间）摊成表单，改一个数字即全库生效，不用写 YAML；②「参考模板校准」：上传一份**学校模板**，逐条量出它的实际格式并反推规则阈值，用户勾选后才写回 |

## 六、几个值得讲的设计细节

**① 格式取值链（本项目最核心的设计）**

Word 里的格式是"继承"出来的。一个段落显示为宋体小四，可能是：

- **直接格式** —— 用户手工选中改的（最容易被误改，也最该被检查）
- **样式** —— 挂了"正文"样式，跟着样式走
- **文档默认值** —— 谁都没设，是 `docDefaults` 给的

只报"实际字号 = 12pt"是没有指导意义的；报"**实际 12pt（来自样式『正文』），规范要求 12pt**"
和报"**实际 14pt（直接格式），规范要求 12pt，建议清除直接格式**"——后者的整改动作完全不同。

所以解析阶段对**每个属性**同时记录生效值与来源，检查引擎据此生成带原因的建议。

**② 规则是数据，不是代码**

引擎只认识 16 个"检查器"（`prop_equals`、`consistency`、`numbering_continuous` …），
完全不知道"毕业论文要求 A4 纸、上下边距 2.54cm"这类具体规则。
换一套规范（比如换成硕士学位论文规范），只需要换一份 YAML，代码一行不动。

**③ 判不准就明说**

有些规则在特定文档里根本无法判定（比如"参考文献条目应含著录要素"，
但文档里压根没有参考文献章节）。这时规则状态记为 `unknown`，
在报告里单独归入「**待人工确认**」，并且**从评分分母中剔除**——
不让"无法判定"变成"扣分项"，这是"宁可漏报不误报"的具体落地。

**④ 修复为什么不激进**

写 `.docx` 时，一旦给段落新增直接格式，就等于把用户原有的样式继承链"焊死"了。
所以修复模块只处理四类**不会改坏语义**的问题，且：
`一律生成新文件 → 记录改了哪几处 → 提供下载`，原文件在磁盘上纹丝不动。

**⑤ 「规则从模板来」是怎么做到一行硬编码都没有的**

内置的 56 条规则是**手工写的通用本科规范**（阈值取自"上下 2.5cm、左 3.0cm、右 2.5cm，
正文宋体小四、1.5 倍行距"这一常见口径），**不是**从某份官方文件里抄来的，
也没有任何一所学校的授权。学校要求不一样怎么办？这正是「参考模板校准」要解决的：

每条规则自己声明了"用哪个 checker、量哪个属性（`params.prop`）、量哪些段落
（`params.scope` / `target`）"。所以"读模板 → 改规则"可以写成一条完全通用的流水线：

```
遍历规则 → 用规则自己的 scope/prop 去模板里量一遍 → 取众数 → 生成提案 → 用户勾选后写回 params
```

因此**新增一条规则，模板推导能力自动覆盖它**，`core/template.py` 一行都不用改。
另外两个刻意的选择：

- 取**众数**而不是平均值——模板里偶发的一两处异常格式不会带偏结论；
- 每条提案都带「占比」（众数出现次数 / 样本数，即置信度），占比低于 80% 会在界面上标黄，
  提醒用户"这个模板本身就不统一，别拿它当标准"。

而且推导结果**不会自动生效**，必须逐条勾选后点「应用到规则集」——
把判断权留在人手里，是这个功能能被信任的前提。

## 八、技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python 3.13 + FastAPI + uvicorn | 轻量、自带 OpenAPI 文档（`/docs`） |
| 文档处理 | python-docx | 直接读 OOXML，可拿到样式与直接格式 |
| 存储 | SQLite（标准库 `sqlite3`，不用 ORM） | 零部署，元数据与报告快照 |
| 规则 | YAML | 规则即数据，可热改、可导出 |
| 前端 | Vue 3 + Element Plus（全局构建，本地资源） | 无构建步骤，双击即用，断网可用 |
| 验证 | pytest + httpx + 无头 Chrome（CDP） | 单元 + 真实端口端到端 + DOM 级烟测 |

> 全项目约 7800 行代码，其中核心引擎（`core/`）约 2500 行，测试约 1000 行。
